# 报告生成 Skill

将渗透测试结果整理为结构化报告，包含详细发现、PoC 脚本和修复建议。

## 报告结构

### 1. 项目概述
- 测试目标
- 测试时间
- 测试范围
- 测试方法

### 2. 执行摘要
- 高危发现概览
- 风险等级分布
- 关键建议

### 3. 详细发现
对每个漏洞：
- 漏洞名称和严重等级
- 漏洞类型
- 影响范围
- 验证步骤
- 关键证据（请求/响应/截图）
- PoC 脚本
- 修复建议

### 4. 攻击路径
- 完整攻击链图示
- 从初始访问到最终目标的路径

### 5. 附件
- PoC 脚本
- 流量抓包
- 截图证据

## 判据：什么不算漏洞

> 这一段与 `vulnclaw/report/triage.py` 的规则表一一对应。代码会按同一份判据
> 拦截 `report_finding(verified=true)`，并把命中的项移出报告的「详细发现」。
> 改判据要同时改两处。

**两个方向都要成立**：既不能把不成立的报成漏洞，也不能把成立的判成不算。
判据命中只说明**形态**可疑；只要给出可测量的后果（读到了什么数据、绕过了哪个
认证、改变了什么状态），就转成「需人工确认」，而不是直接排除。

### 命中即不成立的形态（除非另有后果证明）

| 形态 | 为什么不算 | 要补什么才算 |
|---|---|---|
| 模板 / 规则命中、POC 命中 | 线索不是结论 | 一次手工复现（命令 + 响应） |
| 指纹、组件识别 | 知道用什么 ≠ 能利用 | 该版本可复现的利用结果 |
| 版本号 / banner / Server 头泄露 | 加固建议 | 该版本可实际利用的证据 |
| 开放端口 | 暴露面 | 该服务的未授权访问或危险配置 |
| 缺安全头（CSP / HSTS / X-Frame-Options） | 加固建议 | 可测量的后果（被劫持、被嵌入） |
| 弱 TLS / 证书问题 | 配置项 | 中间人或降级成功的证据 |
| CORS 反射、`Access-Control-Allow-Origin: *` | 单独不成立 | 能读到受保护数据，或带凭据生效 |
| 开放重定向 | 单独不成立 | 串成钓鱼或令牌窃取链路 |
| GraphQL 自省 | 侦察 | 越权查询或敏感字段读取的结果 |
| self-XSS | 只影响自己 | 能影响他人的触发路径 |
| 目录列表（无敏感内容） | 不算泄露 | 其中的凭据、源码或配置 |
| 只给了 CVE 编号 | 情报 | 目标版本上的复现结果 |
| 低价值表单无限速 | 单独不成立 | 爆破出有效凭据，或造成资源耗尽 |
| 内部域名 / 桶名 / 拓扑 | 架构信息 | 凭据、个人信息或进一步利用 |
| `.js.map` / 源码泄露 | 单独不成立 | 其中的密钥、内部接口，且证明可用 |
| Cookie 缺 Secure / HttpOnly / SameSite | 加固建议 | 可实际利用的会话窃取路径 |
| 凭据泄露（token / key / 密码） | 泄露 ≠ 可用 | 用该凭据实际访问一次并保留响应 |

### 判定写在哪儿

- `title` / `description` / `evidence` / `vuln_type` 都会参与匹配——只把非漏洞
  形态写进标题、正文里绝口不提后果，同样会被判为不成立。
- 后果必须落在 `impact`，或在正文里写清实际发生了什么（「读取到 200 条用户记录」
  「绕过 CAS 后返回课程数据」「SLEEP(5) 实测延迟」）。写「存在风险」「影响较大」
  不算后果。
- 被判不成立的项**不会消失**：报告末尾有「已排除项」附录，逐条带规则 id 和理由。
  如果认为判错了，补上表里「要补什么」那一列后重新上报。

### 什么时候该主动放弃

一个分支连续多次负向探测仍然没有证据时，判 `not_confirmed` 或 `inconclusive`
并记录已尝试的命令，比继续机械地试探更有价值——这也是报告里能写的东西。
