# 知识竞赛答题工作流（Playbook）

> 用途：CTF/安全竞赛知识竞赛环节的完整操作细节。正文由 `load_skill_reference`
> 按需加载，不自动注入。

## 一、赛前准备（1-2 分钟内完成）

1. 找到答题入口后，**先抓取整卷**：`fetch` 答题页，确认题目总数、题型分布
   （单选/多选/判断/填空）、是否限时、能否回退修改。
2. 把题目文本完整存入证据（evidence），后续作答全部基于这份文本，不要凭
   印象答题。
3. 若平台要求逐题提交，记录每题的提交参数（题目 id / 选项 value），避免交
   卷时张冠李戴。

## 二、题型对策

### 单选题

- 先看问法是"正确的是"还是"错误的是"——**否定问法是最常见丢分点**。
- 涉及数字（日期/数量/时长/罚款金额）的选项，优先用法规原文核对。
- "以上都是/以上都不对"选项：只要能确认两条子命题成立即为真，通常可选。

### 多选题

- 宁多勿少是常见策略但非绝对：先确定"必对"选项，再评估存疑选项。
- 法律类多选题中，出现"应当"的表述多为正确项，出现"可以自行"的表述多为
  干扰项。
- 按平台格式输出全部字母（如 `ABC`/`A,B,C`），漏选可能整题零分。

### 判断题

- 注意绝对化表述（"所有""任何""一定"）大概率错误；"鼓励""可以""逐步"
  表述大概率正确——仅作启发，不替代知识判断。
- 对/错要与平台文案一致（对/错、正确/错误、√/×、True/False）。

### 填空/简答

- 优先写标准术语全称（如"网络安全等级保护制度"而非"等保"）。
- 涉及条文序号的，写"第 N 条"前务必核对，记不准就写内容不写序号。

## 三、答题纪律

1. **唯一允许的交互 = 读题 + 交卷**。对答题平台做目录扫描/注入/爆破属于
   违规且浪费比赛时间，题目本身没有 Web 漏洞。
2. 交卷前**逐题核对题号-答案映射**，尤其逐题提交的平台。
3. 提交后核对平台返回（得分/剩余次数），失败按返回信息修正格式重交。
4. 时间盒：单题超过 2 分钟无把握就先标记跳过，全卷过完再回来收尾。

## 四、不确定时的优先级

1. **知识范围外的题（当年时事/主题/届数/新文件）不猜**：先翻平台首页、
   公告页、题面背景材料找线索；仍无把握则用红色 `🔴 超纲题` 前缀标记题号
   与题干原文，附上相关资料线索（可能出处的法规/文件名、建议检索关键词、
   对应 skill reference、平台公告页），随即继续做后面的题。**交卷前**以
   `🔴 超纲题汇总` 列出全部超纲题并 `ASK_USER:` 请用户作答——拿到用户答案
   合并后才做唯一一次最终提交，**不得在超纲题未答时抢先交卷**。
2. 排除法猜测仅适用于"知识范围内但没把握"的题；超纲题只有用户明确表示
   放弃作答时才降级猜测。
3. 法律题在 reference（`cn-cybersec-law-baseline.md`）里检索关键词。
4. 相近数字选项（日期/金额），选与已知锚点（如网安法 2017-06-01）同源的。
