# 应急响应 Skill

被入侵服务器的**恶意程序**与**恶意行为痕迹**排查。目标导向：先分型，再按面排查，最后把答案锚在证据上。

**与渗透类 skill 的根本区别**：渗透是从外向内打，应急是从系统内部向外还原攻击链。**提示信息（题目给的线索）是第一优先级**，不要抛开提示盲目全盘扫。

## 五条铁律

1. **先读提示，再动手**。题目给的现象/提示往往直接指向事件类型和排查面。无提示时按下方"分型判据"自行分类。
2. **结论必须挂证据**。任何"这是恶意的""攻击者是 X"的判断，都要能指向具体命令输出。凭印象判断 = 丢分。
3. **不过度发散**。不是每个 Webshell 事件都有系统级后门。查完主面若"系统排查无异常"，**收手换题**，别在一条分支上耗死时间。
4. **路径不许脑补**（见下节"路径证据纪律"）。URL 路径 ≠ 文件系统路径，**禁止自动补 `/var/www/html` 之类的 web 根前缀**。
5. **标注证据类型**（见下节"证据类型标注"）。`[观测]` / `[推断]` / `[知识]` 三档，**不许把后两档写成第一档的语气**。

## ⚠️ 路径证据纪律（实测踩过的坑）

应急响应题**经常直接问"恶意文件的完整路径"**，答错就是丢分。而这个错误会**伪装成正确答案**——因为补出来的路径看起来完全合理。

**规则：报告里每个路径，只能用下面三种原样形式之一**

| 证据来自 | 允许的写法 | 禁止 |
|---|---|---|
| 命令输出（`ps` / `lsof` / `stat` / `find` / `ls`） | 绝对路径原样 | — |
| URL | **URL 原样**，或"web 根下相对路径 `uploads/x.php`" | ❌ 给 URL 补 `/var/www/html` 前缀 |
| 进程 cmdline | 绝对路径原样 | — |

**核心约束**：**web 根位置是未知量，不能假设。**

```
❌ 观测到 URL:  http://target/uploads/a7f3c1.jpg.php
   报告写成:    /var/www/html/uploads/a7f3c1.jpg.php        ← 前缀是编的！

✅ 报告写成:    URL: http://target/uploads/a7f3c1.jpg.php
               （web 根下相对路径 uploads/a7f3c1.jpg.php；
                 绝对路径未观测到——需查 Web 配置才能确定）
```

**要拿到真实绝对路径，得去找证据**：中间件配置（`nginx.conf` 的 `root`、Apache `DocumentRoot`、IIS 站点物理路径）、`/proc/<PID>/cwd`、`lsof` 输出、进程 cmdline。**拿不到就明说拿不到。**

> 实测教训：模型会从 URL 结构"翻译"出看似合理的文件系统路径并**以确定语气写入报告**，
> 报告里没有任何"推测"标记，极难被发现。

## ⚠️ 证据类型标注

每条关键结论后标注来源档次，否则"知识"会被当成"观测"：

| 标注 | 含义 | 写法 |
|---|---|---|
| `[观测]` | 命令/接口的直接输出 | 附 evidence id 或原文片段 |
| `[推断]` | 由观测推出 | **写明推理链** |
| `[知识]` | 来自参考文档的经验，**未在本机验证** | 明确说"未验证" |

**为什么必须区分**：参考文档里的判据（如"`.dotfile` 在 `ls -l` 里看不到"）是**通用知识**，
不代表**本次目标**确实如此。**不能因为文档这么写就当成观测结论。**

```
❌ ".cache_update.sh 需用 ls -al 才看得到"        ← 若从未在本机跑过 ls -al，这是[知识]
✅ "[知识] 通用情况下 dotfile 需 ls -al；本机未验证（无 shell，仅有 HTTP 接口）"
```

**还有一个反直觉的坑**：**题目里给的提示会抑制验证行为**。提示说"有些痕迹需要 `ls -al`"，
模型就容易直接复述这句话而不去验证。**提示是线索不是结论，仍要自己取证。**

## 第一步：事件分型（进场先做这一步）

看现象，对照下表定性。**判据来自《网络安全应急响应技术实战指南》第 4/5/6/7 章。**

| 现象 | 判定 | 加载 |
|---|---|---|
| 文件后缀被改、出现勒索信、桌面新增文本文件 | **勒索病毒** | `events/ransomware.md` |
| CPU 飙升 / 卡顿 / 连接矿池地址 | **挖矿木马** | `events/cryptomining.md` |
| 站点有可疑脚本、暗链、后门告警、页面跳转 | **Webshell** | `events/webshell.md` |
| 首页被篡改、挂黑链、搜索引擎/移动端跳转 | **网页篡改 / 流量劫持** | `events/web-defacement.md` |
| 管理员账号被改、多出账号、登录异常 | **账号类事件** | `20-accounts.md` + `40-log-analysis.md` |
| 只有"找到恶意程序/痕迹"这类泛问 | **先按面扫** | `10-system-basics.md` → `20-accounts.md` → `30-file-artifacts.md` |

> ⚠️ 分型不要只看一个现象。勒索也会 `CPU 高`，挖矿也可能带 Webshell。**交叉验证后再定**。

## 关键心法（来自真实案例）

**1. 文件完整性校验 > 特征查杀**
免杀 Webshell 藏在数万行代码里，特征库里没有。**拿纯净源码算 hash 对比部署文件，输出新增/修改/删除列表**——这是《指南》第 1 章第 4 篇给的答案，也是应对"扫不出来"的正解。

**2. 时间线是主轴**
文件创建时间 → 圈定日志时间窗 → 找可疑访问 → 定位漏洞点。**先锚时间，再找因果**。日志时区与系统时间不一致时必须先校正。

**3. 清除不能只删文件**
落库型后门（数据库里存着生成 Webshell 的 SQL）**删了文件会被重新生成**。清除方案必须同时清数据库记录。见 `events/webshell.md`。

**4. 攻击者会擦痕迹**
`history -c`、`set +o history`、`sed -i '150,$d' .bash_history`、`chattr +i` 锁文件、`/etc/ld.so.preload` 隐藏进程、时间戳伪造（`touch -r`）。
**痕迹"缺失"本身也是线索**——日志空窗、历史记录行数异常都是信号。

**5. 先止血再取证**
只读优先。若要停进程/删文件，**先保存证据**（进程内存副本、文件 hash、原始日志）。真实案例里攻击者的二进制常已自删除，只剩 `/proc/PID/exe` 可捞。

**远程实操（SSH）**

目标是**另一台机器**（给你 SSH 访问）而不是本地时，不要用 `shell_command` 拼
`ssh` 命令 —— 用 `remote_*` 工具，它们是按"主机清单 + 审批"设计的：

| 工具 | 用途 |
|---|---|
| `remote_hosts` | 先看有哪些已配置的主机别名 |
| `remote_collect` | ⭐ 一次性只读采集 33 段并拉回本地（现场固化，最先做） |
| `remote_exec` | 在远程跑单条命令（走**同一个**只读审批门） |
| `remote_fetch` | SFTP 取单个大文件/二进制（内存镜像、pcap） |

> ⚠️ 远程命令与本地命令受**同一套只读分类器**管辖：`ps aux` 免批准，
> `rm` 会弹窗。别试图绕过审批门。

## 合规与留痕

- **严格限定在授权范围内**。比赛场景：只碰自己工位的靶机网段，**绝不对计分平台/赛事系统/第三方服务发起任何请求**（违规直接取消资格）。
- **保留完整操作记录**：每条命令 + 输出 + 时间戳。赛后可能抽查答题思路与系统日志。
- 取证类操作尽量**只读**；必须修改系统状态时先记录原值。
