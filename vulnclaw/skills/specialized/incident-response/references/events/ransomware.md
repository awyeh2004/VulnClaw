# 勒索病毒应急响应

勒索病毒题的**现象最直观**（一打开就发现文件打不开、桌面有勒索信），但**处置最容易犯错**——
《指南》第 4 章专门单列了一节「**错误处置方法**」，这是七类事件里唯一这么做的。

**主流程**：`初步预判 → 隔离 → 排范围 → 定种类溯源 → 恢复 → 加固`

---

## 一、⭐ 初步预判：四项判据

> 注意：单项判据都**不是 100% 确定**，要交叉验证。

| # | 判据 | 说明 |
|---|---|---|
| 1 | **业务系统无法访问** | 勒索病毒不仅加密核心业务文件，还攻击服务器和业务系统，甚至延伸到生产线（生产线有遗留系统、硬件难打补丁，一旦中招就停工停产）<br>⚠️ **但业务不可访问也可能是 DDoS 或其他病毒** —— 需结合下面三项 |
| 2 | ⭐ **文件后缀被篡改** | 可执行文件、文档被改成特定后缀，如 `.bomber` |
| 3 | ⭐ **勒索信展示** | 通常在**桌面**或**磁盘根目录**。内容含：文件被加密的提示、如何支付赎金、支付剩余时间，一般提供多语言选项 |
| 4 | **桌面有新文本文件** | 除勒索信外，桌面常生成新文本文件，内容是加密信息、解密联系方式 |

**判据要点**：**后缀被改 + 勒索信**这两条基本就定性了。

### 判断加密时间

> 了解**被加密文件的修改时间**及**勒索信建立时间**，推断攻击者执行勒索程序的时间轴。

**Windows**：看文件修改日期（资源管理器按修改日期排序）

**Linux**：用 `stat`，重点看两个时间：

```bash
stat /etc/passwd
```

| 字段 | 用途 |
|---|---|
| `Modify` | **内容修改时间** → 判断文件加密时间 |
| `Change` | **属性变更时间** → 判断是否存在系统文件被修改或系统命令被替换 |

> ⭐ 从这两个时间节点可以判断"**是否存在系统文件被修改或系统命令被替换**"——
> 勒索常伴随系统命令替换（用于擦痕迹或长期驻留）。

### 判断"中招"范围

- 有集中管控软件/全流量设备 → 直接查
- 没有 → 通过 IT 管理员收集网络信息：**先查同网段，再扩展到相邻网段**
- 收集内部人员反馈补充

> ⚠️ **为什么必须查范围**：有一类勒索病毒通过系统漏洞或弱密码横向传播。
> **WannaCry 一旦有一台中招，同网段其他机器会迅速被感染，每台约 1–2 分钟。**
> 不及时隔离可能导致**整个局域网瘫痪**。

### 了解系统架构

收集操作系统版本、开放端口、中间件版本、数据库类型、Web 框架 → 判断应用/中间件是否存在漏洞。

## 二、⚠️⭐ 错误处置方法（最容易丢分的地方）

《指南》单列一节，**应急处置题经常直接考"以下哪些做法是错误的"**。

### ❌ 错误 1：使用移动存储设备

| | |
|---|---|
| **错误操作** | 确认中招后，在中招机器上插 U 盘、移动硬盘 |
| **错误原理** | 勒索病毒对感染主机上的所有文件加密，**插上移动存储会立即把里面的内容也加密**，损失扩大 |

> **正确做法**：隔离时**拔掉所有外部存储设备**，而不是插新的。

### ❌ 错误 2：反复读/写中招主机的磁盘文件

| | |
|---|---|
| **错误操作** | 轻信网上各种解密方法/工具，反复读/写磁盘文件 |
| **错误原理** | 很多勒索病毒的基本加密流程是：<br>① 磁盘文件读入内存 → ② 内存中加密 → ③ 写回磁盘 → ④ **删除原始文件**<br>理论上有专用数据恢复软件可能部分/全部恢复被加密文件，<br>但**反复读/写会破坏磁盘空间中的原始文件**，导致原本还有希望恢复的**彻底无法恢复** |

> **正确做法**：**先断电/停止业务，再考虑恢复**。不要在中招盘上瞎折腾。

### 其它错误做法

| 错误 | 后果 |
|---|---|
| 不停机就删除勒索信/加密文件 | 破坏时间线证据，且可能触发二次加密 |
| 只清理病毒不查入侵途径 | 立刻二次入侵 |
| 直接支付赎金 | 不保证解密，且可能被标记为优质目标 |

## 三、常规处置五步（4.2）

```
① 隔离被感染的服务器/主机
② 排查业务系统（含备份系统！）
③ 确定勒索病毒种类，溯源分析
④ 恢复数据和业务
⑤ 后续防护建议
```

### ① 隔离

**目的**：一是防止通过网络继续感染其他机器；二是防止攻击者通过该机器继续操控其他设备。

| 手段 | 做法 |
|---|---|
| **物理隔离** | 断网或断电、关闭无线网络/蓝牙、**禁用网卡**、**拔掉所有外部存储设备** |
| **访问控制** | 对网络资源访问权限严格认证和控制（加策略、改登录密码） |

> ⚠️ 攻击者会**以暴露在公网的机器为跳板**，再顺藤摸瓜找到核心业务服务器。
> **隔离要快，且要考虑"谁是跳板、谁是目标"。**

### ② 排查业务系统

**业务系统受影响程度直接决定事件风险等级。**

隔离后立即排查：
- 局域网内其他机器
- **核心业务系统是否受影响**
- **生产线是否受影响**
- ⭐ **备份系统是否被加密**

> ⭐ **备份系统是安全的 → 可以避免支付赎金，顺利恢复文件。**
> 所以"**备份有没有被加密**"是这一节最关键的问题。

### ③ 确定种类 + 溯源

**先找勒索提示信息**，其中常含勒索病毒标识 → 直接判断种类 → 查是否有解密工具。

**溯源**：查服务器上保留的**日志和样本**
- 日志能判断勒索病毒通过哪种方法侵入
- **日志被删除** → 在机器上找**病毒样本或可疑文件**，通过这些文件反推入侵途径

**日志分析的线索**（真实案例）：

> 真实案例中通过日志分析工具发现**可疑的横向移动 PSEXEC 工具利用行为**。
> PSEXEC 是轻量级 Telnet 替代工具，**无须手动安装客户端即可执行进程**，
> 也可获得与控制台应用程序相同的交互，**是攻击者常用的远程操作工具**。
> 案例里定位到 PSEXEC 在 `2019.11.26 21:30:39` 被**攻击者手动启动** —— 这条时间戳是后续判断异常操作的参考依据。

⭐ **判据**：日志里出现 `PSEXEC` / `psexec` / `PsExec64.exe` ⇒ **横向移动信号**。

### ④ 恢复数据和业务

| 情况 | 做法 |
|---|---|
| **有数据备份** | ⭐ 直接还原备份恢复业务（首选） |
| 无备份，但确定种类 | 查对应解密工具 |
| 数据重要且业务急需恢复 | ① 磁盘数据恢复手段恢复被删除的文件<br>② 向第三方解密中介/安全公司求助 |

### ⑤ 后续防护（四层）

**服务器/终端**：强密码策略杜绝弱密码、**杜绝通用密码管所有机器**、装杀软并及时更新病毒库、及时打补丁、**开启关键日志收集**（为溯源提供支撑）

**网络**：合理划分安全域 + 域间严格 ACL（限制横向移动范围）；重要业务系统与核心数据库**设独立安全区域**、关闭 Telnet/SNMP 等不必要服务；架 IDS/IPS 发现阻断横向移动；架全流量记录设备

**应用与备份**：渗透测试与加固；**及时备份并定期验证备份可用性**；建安全灾备预案，**做好备份系统与主系统的安全隔离**（避免同时被攻击）

## 四、技术操作指南（4.5）

```
初步预判 → 临时处置 → 系统排查 → 日志排查 → 网络流量排查 → 清除加固
```

### 排查要点

**系统排查**（沿用通用面，见 `../10-system-basics.md` 等）：

- 账号（新增/隐藏/克隆）
- 进程（异常 CPU、随机名）
- 服务、启动项、计划任务
- **文件**：`temp` 目录、各大盘符敏感目录、按时间点圈定
- ⭐ **文件时间戳逻辑**：修改时间与创建时间矛盾的文件优先

**日志排查**：

```bash
# Linux
grep "Failed password" /var/log/secure        # 爆破进来的？
grep "Accepted " /var/log/secure              # 成功登录
grep -iE 'psexec|wmic|powershell' /var/log/messages
last ; lastb ; lastlog

# Windows
# 安全日志：4624/4625（登录）、4720（建用户）、7045（建服务）
# ⭐ 注意 1102（清理审计日志）—— 出现即攻击者擦痕迹
```

**网络流量排查**：横向移动特征（SMB 445 大量连接、PsExec 流量、异常 RDP）

### 清除加固

发现 **rootkit 类后门** → **建议重装系统**（《指南》第 6 章同款建议）。

## 五、⭐ 勒索病毒查询与解密工具

**判断能否解密**是这类事件的核心诉求之一。

| 平台 | 用途 |
|---|---|
| **奇安信勒索病毒搜索引擎** | ⭐ 支持检索 **800+ 种**常见勒索病毒。输入**攻击者邮箱**、**被加密文件的新后缀**，或上传**被加密文件/勒索提示信息**即可查询。例如输入 `WannaCry` 可直接下载解密工具 |
| 360 安全卫士勒索病毒搜索引擎 | 同类 |
| 腾讯管家勒索病毒搜索引擎 | 同类 |
| **ID Ransomware** | 国际主流，按后缀/邮箱识别 |
| **No More Ransom** | 欧洲刑警组织等联合项目 |
| 趋势科技 / 卡巴斯基 / EMSISOFT / Avast / Quick Heal | 各家解密工具 |

⭐ **查询三要素**（拿到任一个就能查）：
1. **被加密文件的新后缀**（如 `.bomber`）
2. **攻击者邮箱**（勒索信里通常有）
3. **勒索信原文 / 被加密样本**

### 日志分析工具

- **观星实验室应急响应信息采集工具** —— 采集系统日志 + 进程列表 + 系统服务 + 启动项 + 系统补丁 + 计划任务，自动打包上传分析平台
- 分析平台可自动识别**可疑威胁概览**与**暴力破解记录**，并发现**横向移动工具利用**（如 PsExec）

## 六、常见问法与答法

| 问 | 答什么 | 依据 |
|---|---|---|
| 中了什么勒索病毒 | 从**后缀** / **勒索信** / **攻击者邮箱**判断 | 勒索信 + 查询平台 |
| 能不能解密 | 查勒索病毒搜索引擎的结论 | 后缀/邮箱查询 |
| 加密时间 | 被加密文件的 `Modify` 时间 / 勒索信建立时间 | `stat` / 文件属性 |
| 什么时间被入侵的 | 日志（登录、服务创建、横向移动工具） | 事件日志 |
| 怎么进来的 | 弱密码爆破 / 系统漏洞（WannaCry 永恒之蓝）/ RDP 暴露 | `secure` 日志 / 事件 ID |
| 感染范围多大 | 同网段 + 相邻网段排查；备份系统是否被加密 | 网络信息 + 备份检查 |
| **哪些处置是错的** | ⭐ **用移动存储设备** + **反复读/写磁盘** | 第 4.3 节 |
| 怎么恢复 | 有备份优先还原；无备份查解密工具；实在不行数据恢复 | 4.2.4 |
| 后续怎么防 | 强密码/去掉通用密码/打补丁/分安全域/备份隔离 | 4.2.5 |

## 七、⭐⭐ 三个必须记住的判断

**1. 先隔离，且隔离时拔掉外部存储而不是插新的**
WannaCry 类每台机器 1–2 分钟就能感染下一台，整个局域网可能瘫痪。

**2. 反复读/写中招磁盘 = 自毁恢复希望**
勒索病毒的加密流程含"**删除原始文件**"这一步。理论上数据恢复软件还能救，
**反复读写会把原始文件覆盖掉**。

**3. 备份系统是否被加密，决定要不要付赎金**
备份安全 → 直接还原；备份被加密 → 才需要考虑解密工具或第三方。
